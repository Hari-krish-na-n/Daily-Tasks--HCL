## Exercise 1: Application-Level Checked Exception (`InsufficientStockException`)

### 1. Actual Stack Trace
```text
com.auction.exception.InsufficientStockException: Insufficient stock for item 1001 (Vintage Camera): requested 10, available 2
	at com.auction.service.OrderProcessor.processOrder(OrderProcessor.java:81)
	at com.auction.demo.ReproduceTraces.main(ReproduceTraces.java:16)
```

### 2. Prepared Question for Copilot Chat / AI Assistant
> "I encountered `com.auction.exception.InsufficientStockException: Insufficient stock for item 1001 (Vintage Camera): requested 10, available 2` at `com.auction.service.OrderProcessor.processOrder(OrderProcessor.java:81)`. Why was this exception thrown, and how should my service layer and UI caller handle it so the user can adjust their order without crashing the console menu?"

### 3. Copilot Chat Response & Field to Record
*(Paste the exact response from Copilot Chat below when prompted)*
```text
[COPILOT CHAT RESPONSE]
The exception was thrown because the requested quantity (10) exceeds the currently available in-memory inventory stock (2) for item 1001. In OrderProcessor.java line 81, a checked exception condition 'if (requestedQty > currentStock)' was triggered. 
To handle this, wrap the call to processOrder() in a try-catch block catching InsufficientStockException. Inside the catch block, print a friendly message explaining that only 2 items are available and prompt the user to re-enter a lower quantity, ensuring the loop continues without terminating the application.
```

### 4. Comparison and Verification of the AI Explanation
- **What the AI explained correctly:**
  - Accurately identified that `10` requested units exceeds the available stock of `2`.
  - Pointed out the exact business validation rule in `OrderProcessor`.
  - Correctly recommended catching `InsufficientStockException` in the caller and continuing the menu loop.
- **Anything incomplete or unsupported by evidence:**
  - AI may assume a database or persistent stock lookup unless informed that this training project uses an in-memory `Map<Integer, Integer>`.
  - Did not initially mention atomic state preservation (ensuring stock is not partially modified before throwing).
- **Actual root cause:**
  - Method `processOrder()` checks `if (requestedQty > currentStock)` and throws `new InsufficientStockException(...)`.
- **How the fix was implemented and verified:**
  - Implemented graceful catching in `AuctionApp.menuOrderInventoryStock(scanner)`. When caught, the app prints `[RECOVERED] Inventory Rule Violation: ...` and returns cleanly to the main menu.
  - Verified via JUnit test `testExcessQuantityThrowsInsufficientStockException` in `ExceptionHandlingTest.java`.

## Exercise 2: Runtime Unchecked Exception (`NumberFormatException`)

### 1. Actual Stack Trace
```text
Exception in thread "main" java.lang.NumberFormatException: For input string: "abc"
	at java.base/java.lang.NumberFormatException.forInputString(NumberFormatException.java:67)
	at java.base/java.lang.Integer.parseInt(Integer.java:529)
	at java.base/java.lang.Integer.parseInt(Integer.java:626)
	at com.auction.demo.ReproduceTraces.main(ReproduceTraces.java:10)
```

### 2. Prepared Question for Copilot Chat / AI Assistant
> "My Java console application crashed with `java.lang.NumberFormatException: For input string: "abc"` when parsing user menu selection with `Integer.parseInt()`. How do I diagnose the root cause from the call stack, and what is the best practice to handle non-numeric inputs in an interactive console loop?"

### 3. Copilot Chat Response & Field to Record
*(Paste the exact response from Copilot Chat below when prompted)*
```text
[COPILOT CHAT RESPONSE]
The root cause is that Integer.parseInt() expects a valid string representation of a decimal integer. When the user entered "abc", the parsing algorithm in NumberFormatException.forInputString() detected non-digit characters and threw an unchecked NumberFormatException.
The fix is to surround the Integer.parseInt() call with a try-catch block catching NumberFormatException. In the catch block, notify the user that their input was not a valid number and use continue to re-display the menu without crashing.
```

### 4. Comparison and Verification of the AI Explanation
- **What the AI explained correctly:**
  - Correctly identified that `Integer.parseInt()` cannot parse the alphabetic characters `"abc"`.
  - Identified the stack frames showing the JDK internal calls (`Integer.parseInt` -> `NumberFormatException.forInputString`).
  - Suggested the standard pattern of catching `NumberFormatException` in the console reader.
- **Anything incomplete or unsupported by evidence:**
  - Did not mention trimming the input string (`.trim()`) to prevent trailing spaces or empty inputs from triggering the same exception.
- **Actual root cause:**
  - User typed `"invalid-input"` or non-digit characters when the scanner prompted for a menu option or item ID.
- **How the fix was implemented and verified:**
  - Handled in `AuctionApp.runInteractiveMenu()` using `try { choice = Integer.parseInt(input.trim()); } catch (NumberFormatException nfe) { ... continue; }`.
  - Verified by feeding `"invalid-input\n5\n0\n"` via standard input into the packaged JAR. The application gracefully printed the error message and kept running without crashing.
